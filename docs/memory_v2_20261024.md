# 记忆系统 v2：短期会话台账 + 长期用户记忆（2026-10-24）

v1 见 [context_manager_memory_v1_2026_06_21.md](context_manager_memory_v1_2026_06_21.md)。v2 参考 Google 开源的 Harness² 中关于记忆的设计（`harness2/core/library.py`、`prompts.experience`、常驻记忆组件 `LongTermMEMORY.md`），修复 100 轮长对话测试暴露的问题，并实现原本只停留在设计里的长期记忆。

## 一、借鉴的五条原则

| Harness² 的做法 | 本项目中的对应实现 |
| --- | --- |
| 两层记忆：常驻记忆短小、有预算（"加一条就删一条"）；经验库按需打开 | 会话台账每轮都会带上，但条目数有预算；长期记忆常驻段不超过 300 字 |
| 索引 + cue：先看 `INDEX.md` 里每条的适用情形，再打开相关条目 | 逐轮线索台账 `turn_notes`：每轮记一条原话线索；用户说"第 N 轮""最开始"时才定位到具体条目 |
| 写入门槛：至多写一条，证据不足写 `NO_ENTRY` | 长期记忆默认不写，只有用户明确表达的长期偏好或关注领域才写入，并附原话出处 |
| 具体事实不进长期记忆，写入前检查有无泄漏 | 新闻事实、用户记得的数字、持仓、个人信息一律拒写 |
| 条目可保留、可遗忘 | 用户可通过 `/api/ai/memory` 查看、删除、清空；超出预算时淘汰最久未使用的条目 |

## 二、短期记忆（会话内）

### 测试发现的问题（v1，100 轮对话）

| 场景 | v1 表现 | 根因 |
| --- | --- | --- |
| 第 1 轮说"之后都不超过 100 字"，第 100 轮提问 | 写了 144 字 | 约束只从最近 20 条消息里提取，没有从台账延续 |
| 第 50 轮聊童装，第 100 轮问"第 50 轮那个产业" | 回答"没有第 50 轮的记录" | 台账按窗口内的相对位置编号；话题靠固定关键词表识别，表里没有"童装" |
| 第 1 轮问某篇报道，第 100 轮问"那篇是哪天发的" | 答不出 | 第 1 轮引用过的证据编号在 98 轮闲聊后无法再关联 |
| "回到最开始的话题，最近有什么新报道" | 只复述了话题，没有检索 | 被判成"只回忆"的快速通道 |

### v2 的做法

1. **约束延续**：`active_constraints` = 台账里延续下来的约束，再由当前窗口里的新约束覆盖。
2. **绝对轮次**：路由层统计会话里的用户消息数（`count_user_messages`），作为 `session_turn` 传给 agent，台账按真实轮次编号。
3. **逐轮线索台账 `turn_notes`**：每轮记录 `{turn, cue: 原话前 60 字, substantive, evidence_refs: 该轮回答引用的证据}`。
   - 有预算：实质轮次最多保留 40 条，最早 3 条永不淘汰（用于回答"最开始……"）；闲聊最多保留 5 条，且最先被淘汰。
4. **指代解析 `resolve_turn_reference`**：识别"第 N 轮"和"最开始/一开始/最初"。命中后：
   - 检索词改为"那一轮的原话 + 本句"；
   - 带回那一轮引用过的证据编号；
   - 提示词里注明"用户指的是第 N 轮：……"。

   记忆只负责指路，事实仍然只来自本轮检索到的证据。
5. **"只回忆"快速通道收窄**：问题里包含"新报道""最近""哪天""怎么说"等词时，正常走检索。

## 三、长期记忆（跨会话，按用户）

- **存储**：表 `ai_user_memory`（建表语句在 `scripts/ai_tables.sql`），每条记录包含 `kind`（preference / interest）、`mem_key`、`value`、`cue`，以及 `evidence`（会话、轮次、用户原话）、使用次数和最近使用时间。
- **写入**（`harness/long_term_memory.py`）：
  - 偏好：必须带有长期标记（以后 / 之后 / 每次 / 默认……）。"这次不超过 50 字"是一次性要求，不写入。
  - 关注领域：识别"我主要关注 / 我关心 / 我感兴趣……"这类说法。
  - 拒写规则：带金额或比例的数字（亿 / 万 / % / 元……）、"我记得 / 听说 / 据说"、持仓与买卖、手机号或身份证等个人信息。
- **预算**：每个用户最多 `LONG_TERM_MEMORY_MAX_ENTRIES` 条（默认 12），超出时淘汰最久未使用的条目。
- **读取**：
  - 常驻段 `<long_term_memory use_as_evidence="false">`，不超过 300 字。
  - 偏好作为默认约束，优先级为：当前这句 > 本会话 > 长期记忆。
  - 关注领域只在用户说"我关注的领域"时才参与检索。
- **用户控制**：`GET /api/ai/memory`、`DELETE /api/ai/memory/{id}`、`DELETE /api/ai/memory`。总开关是 `LONG_TERM_MEMORY_ENABLED`。

## 四、验证

- 单元测试：`tests/test_long_term_memory.py`，以及 `tests/test_context_manager.py` 中的 100 轮回放测试。回放测试完全按路由层的方式运行：每轮只取最近 20 条消息，上一轮的上下文元数据一路传递下去；到第 100 轮时检查第 1 轮、第 50 轮能否定位，第 2 轮的约束是否仍然有效。
- 端到端：`eval/gold/eval_gold_capabilities_20261024.jsonl`，包括长上下文 5 题、长期记忆 4 题、网页与 OCR 4 题。结果见下节。

## 五、端到端结果

在生产配置下运行（DeepSeek 回答，硅基流动负责检索）。长上下文题每题 100 轮，中间 98 轮是闲聊。

| 题目 | v1（CAP1） | v2（CAP2） |
| --- | --- | --- |
| 第 1 轮说关注的话题，第 100 轮问"那个话题最近有什么新报道" | ⚠️ 只复述话题，没有检索 | ✅ 定位到第 1 轮，检索并带引用作答 |
| 第 1 轮定"不超过 100 字"，第 100 轮问"它"的影响 | ⚠️ 写了 144 字 | ✅ 正文 41 字，带引用 |
| 第 1 轮问的报道，第 100 轮问"哪天发的" | ❌ 答不出 | ✅ 2026 年 6 月 7 日，并引用原文 |
| 第 50 轮聊的产业，第 100 轮问"第 50 轮那个产业" | ❌ 回答"没有第 50 轮的记录" | ✅ 定位到童装产业，并引用 3 篇报道 |
| 会话 A 定偏好"以后都不超过 80 字"，会话 B 提问 | 无此功能 | ✅ 37 字 |
| 会话 A 说"我记得苏超带动了 500 亿"，会话 B 问实际数字 | 无此功能 | ✅ 没有写入记忆；回答用证据里的 380 亿元 |
| 会话 A 说"我主要关注童装产业"，会话 B 问"我关注的领域有什么新报道" | 无此功能 | ✅ 回答童装产业的新闻 |
| 清空长期记忆后再问"我关注的领域" | 无此功能 | ✅ 说明还没有记录，没有提到童装 |

指标：话题回忆 2/3 → 3/3，指代回忆 0/1 → 1/1，记忆与证据分离保持 100%，长期记忆题 4/4。

这次验证还发现一个写入门槛漏洞：问句"有什么我关注的领域的新报道"被误记成了关注领域"领域的新"。现在问句以及"我关注的……"这类引用说法都不写入，已加单元测试。
