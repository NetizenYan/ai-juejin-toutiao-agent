## 三、评测本身的可信度

| 问题 | 影响 |
| --- | --- |
| 主集 95 题、补充集 25 题，规模小 | 一题的差异就会让 Hit@5 变动约 0.01–0.04 |
| 调试时看过主集（包括留出部分）的失败案例 | 成绩可能偏乐观；留出集结论只能算弱证据 |
| 回答质量主评委也参与了开发 | 用第二评委和盲评部分对冲，但没有消除 |
| 能力题和安全题每类只有几道 | 能说明"能做到"，不能说明"稳定做到" |

建议增加一批没有参与调试的新题，每类 3–5 题，共约 30 题，作为真正的测试集。

## 四、提升到 90 分以上的路径（按收益排序）

1. **多证据完整性**：EvidenceRecall@5 0.669。多文档题可以考虑扩大精排后保留的条数，或按子问题分别检索。
2. **新题测试集与独立评委**：提升评分本身的可信度，对总分影响最大。
3. **工具性能与架构**：常驻 MCP 进程、OCR 换 GPU 或直接提取网页文本、配置联网搜索。
4. **间接提示注入防护**：把站外内容从 system 角色移到 tool/user 角色，并补测试题。
5. **延迟**：调整提示词顺序以提高缓存命中，对简单题降低思考强度。
