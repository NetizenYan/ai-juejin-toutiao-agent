# 掘金头条 Agent 评测报告（2026-10-24）

本报告汇总 2026-10-21 至 10-24 对新闻问答 Agent 所做的修复和评测，结论均对应最终生产配置。原始逐题结果在 `reports/`（被 git 忽略，可按第十节复现）。

## 一、结论

| 指标（主集 95 道可计分题） | 修复前基线（10-22） | 最终生产配置 R12 |
| --- | ---: | ---: |
| Hit@5（前 5 条命中标准答案） | 0.453 | **0.916** |
| MRR | 0.384 | **0.848** |
| 拒答正确率 | 0.50 | **1.00** |
| 模板兜底回答（115 题中） | 29 | **0** |
| 延迟中位数 / P95 | 14.6s / — | **6.8s / 14.6s** |

- 补充集（人民日报 + 新闻联播 28 题）Hit@5 0.96，拒答正确率 1.0；锚点承接集确认后承接准确率 1.0；端到端 qa_set 15/15。
- 回答质量：两位评委对 DeepSeek 回答的有用率评分分别为 96% 和 86%，本地 qwen3.5:9b 为 65% 和 68%。生产模型因此选用 DeepSeek。
- 每题成本约 0.004 元：DeepSeek 约 0.003 元，硅基流动检索约 0.001 元。

## 二、系统与评测设置

**生产配置**

| 环节 | 选型 |
| --- | --- |
| 回答模型 | DeepSeek-V4.1-Flash（`deepseek-flash`），开启思考，effort=high，超时 120s |
| 检索规划 | `AGENT_TOOL_PLANNING=deterministic`，直接用用户原问题检索 |
| Embedding | 硅基流动 `Pro/BAAI/bge-m3`（1024 维） |
| 精排 | 硅基流动 `Pro/BAAI/bge-reranker-v2-m3` |
| 向量库 | Qdrant：经济/政策集合 10.2 万块，新闻联播集合 |
| 本地测试 | Ollama qwen3.5:9b + 本地 bge-m3 / hf-api 精排，只用于快速、免费的回归测试 |

**语料**

- 经济日报、人民日报经济类报道 20,905 篇，2025-06-10 至 2026-06-10。
- 新闻联播 6,796 篇，2006-09-01 至 2025-04-09。
- "最近"按 2026-06-10 前约 90 天计算（`RAG_RECENCY_REFERENCE_DATE`）。

**题集**

| 题集 | 题数 | 用途 |
| --- | ---: | --- |
| 主集 expanded115 | 115（95 题有标准证据） | 检索、引用、拒答、路由、回答质量 |
| 补充集 | 28（25 题有标准证据） | 人民日报、新闻联播、来源和日期限定 |
| 锚点集 b_v3 | 6 | 多轮对话里"那篇报道"的确认与承接 |
| qa_set | 15 | 闲聊、推荐、业务接口端到端 |
| 主集留出部分 | 35（28 题可计分） | 防过拟合检查，见第七节 |

标准证据在 10-23 经过一轮盲审：删去 19 条与问题不符的证据 ID，人工标注全部保留。本报告中所有轮次都按审后的标注重新计算，口径一致。

**指标**

- **Hit@5**：前 5 条检索结果中至少有一条标准证据。
- **MRR**：第一条命中的标准证据排名的倒数，再取平均。
- **拒答正确率**：应拒答的题是否拒答；投资类问题要求带风险提示，且不出现确定性措辞。
- **模板兜底**：模型回答两次校验都失败后，系统改用的确定性摘要（以"近期相关报道主要聚焦"开头）。

## 三、改进历程

主集全部按 10-23 审后标注重算。

| 轮次 | 回答模型 | 主要变化 | Hit@5 | MRR | 模板 | P50 |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| 基线（10-22） | qwen3.5:9b | 修复前 | 0.453 | 0.384 | 29 | 14.6s |
| R3 | qwen3.5:9b | 锚点、路由、投资拒答修复 | 0.874 | 0.781 | 61 | 25.7s |
| R5 | qwen3.5:9b | 关闭本地思考、日期硬过滤、引用修复 | 0.874 | 0.803 | 10 | 7.0s |
| R7 | qwen3.5:9b | 校验与改写修复、来源别名 | 0.905 | 0.812 | 8 | 7.6s |

## 四、关键问题与修复

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | 44/115 题被锚点确认拦截 | 普通问题也被当成"指代某篇报道" | 只在"我记得/好像有一篇"这类模糊回忆说法时触发 |
| 2 | 部分经济问题只搜了新闻联播 | 路由关键词缺口 | 补关键词；未指定来源时同时检索两个集合 |
| 3 | 投资确定性问题的拒答被替换成证据摘要 | 兜底逻辑不区分问题类型 | 投资确定性问题保留拒答，兜底答案前加风险提示 |
| 4 | 精排完全不起作用 | hf-api 超过 32 个文档时返回 422，代码静默退回召回顺序 | 按 32 条分批、开启截断，失败时记录警告 |
| 5 | 带过滤条件的检索漏召回 | Qdrant 缺 payload 索引 | 建索引后重建 HNSW |
| 6 | 61 题模板兜底 | 本地模型默认开思考，占满 4096 上下文；改写请求以 assistant 消息结尾，模型只会续写 | 本地关闭思考；改写请求改为以 user 消息结尾 |
| 7 | "2026 年 5 月"这类日期限定无效 | 没有日期硬过滤 | 解析明确日期，按 `publish_ts` 区间过滤 |
| 8 | DeepSeek 检索丢失来源和日期 | 模型把问题改写成关键词 | 原问题先检索，各次结果合并后统一精排；生产改为直接用原问题检索 |
| 9 | "只看新闻联播，最近……"用 2024 年报道作答 | 模型补充的检索词去掉了"最近"，绕过过期过滤 | 合并结果同样执行"最近"过滤 |
| 10 | 数字挂错对象（网球公开赛 8000 万写成 CBA） | 校验器只检查数字是否出现在证据里 | 提示词要求数字写在证据中同一句话所说的对象上（效果见第五节） |

## 五、回答质量

**评分方法**

- 从主集抽 40 题（后扩到 52 题）。评委对照所引证据原文，从相关、忠实、完整、遵守约束四个维度各打 0–2 分，再给有用度 1–5 分（≥4 算有用）。
- 正确拒答算有用。数字和名称要核对是否挂在正确对象上。
- 评委有两位：Claude 和 DeepSeek-V4-Pro。去掉拒答题后比较：

| 回答来源 | Claude 评 | Pro 评 |
| --- | ---: | ---: |
| DeepSeek（R9） | 96% | 86% |
| 本地 qwen（R7） | 65% | 68% |

两位评委打分相差不超过 1 分的比例为 91–93%。Claude 对 DeepSeek 偏松，所以真实有用率按 86–96% 这个区间理解。不论按哪位评委，DeepSeek 都比本地模型高约 20 个百分点。

**盲评：R11 对 R12**

参考 Google Harness² 的候选选择做法，把同一题的两个回答随机标成 X/Y，评审时不知道哪个来自哪一轮，并按"忠实 → 切题 → 有用"的顺序判断，长度本身不加分。52 题的结果：

| R12 胜 | R11 胜 | 平局 | 两轮回答完全相同 |
| ---: | ---: | ---: | ---: |
| 8 | 9 | 29 | 6 |

- 两轮质量持平。R12 胜在拒答（source_006）、"最近"类问题用到更新的报道、来源归属更准确。
- R12 输掉的题有一个共同点：数字更少。distractor_008 里 R11 正确写出"苏超单场 6 万人、带动消费 380 亿元"，R12 没写数字；exact_econ_012 里 R12 还错误地说"报道未展开具体指标"。第四节第 10 条新加的约束（"不确定归属的数字宁可不写"）可能让模型过度保守，要用更多题确认。

## 六、检索方案对比

同一套代码、同一题集，只检索不调回答模型：

| | 本地 Ollama + hf-api | 硅基流动 API |
| --- | ---: | ---: |
| 主集 Hit@5 / MRR | 0.916 / 0.853 | 0.916 / 0.848 |
| 补充集 Hit@5 / MRR | 0.96 / 0.92 | 0.96 / 0.92 |
| 检索耗时中位数 | 0.39s | 1.43s |

- 两边是同一套模型：硅基流动与 Ollama 的 bge-m3 向量余弦相似度为 0.9999，所以不需要重建索引。
- 生产选硅基流动，是为了部署时不依赖本地 GPU，代价是每题多约 1 秒。

**主集剩余 8 道漏检题**

- 6 道的标准答案已经召回到前 50 条，是在精排时被挤出了前 5，换 embedding 模型解决不了。
- 另外 2 道（context_follow_001/003）是多轮追问。这次分析只用原问题检索，没有像真实流程那样结合上一轮改写，所以它们是否真的召回失败还不确定。
- 补充集的 cctv_source_004 在各轮都没有命中。它的标准答案也在前 50 条里，同样是精排问题。

## 九、已知局限

1. **数字挂错对象**：校验器拦不住这类错误。提示词约束可能让回答过度省略数字，见第五节。
2. **评委偏差**：主要评委（Claude）同时也是修复的实施者。Pro 只复核了 R7/R9；R11 对 R12 的盲评只有一位评委，且只覆盖 52 题。
3. **题集规模**：主集可计分 95 题，一两题的差异就会让 Hit@5 变动 0.01–0.02。R11 与 R12 之间的检索差异接近这个噪声范围。
4. **新闻联播数据只到 2025-04**：对"最近"类问题只能拒答。
5. **精排上限**：剩余漏检集中在精排阶段。
